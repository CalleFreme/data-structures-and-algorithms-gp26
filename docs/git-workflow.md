# Lightweight Git Workflow

Git is not a separate learning outcome in this course, but we will use it to support a more deliberate development process.

A useful loop is:

1. Start from working code.
2. Understand the next small problem.
3. Make one meaningful change.
4. Build/run/test it.
5. Inspect the result.
6. Commit at a coherent checkpoint.
7. Continue.

Good commits are evidence of stages in your thinking, not a target number to hit.

Example messages:

```text
Implement highest-score lookup
Add edge-case test for empty player collection
Fix queue wrap-around handling
```

Avoid waiting until the entire lab is finished and then making one giant “done” commit.
